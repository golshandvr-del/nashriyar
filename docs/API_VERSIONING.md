# سیاست نسخه‌بندی API و مایگریشن‌های بدون توقف

> ROADMAP فاز ۱۷. این سند قرارداد تغییر API و پایگاه داده را تعریف می‌کند تا سامانه سال‌ها بدون قطعی و بدون شکستن کلاینت‌ها (وب، اپ اندروید آینده، سامانه‌های دیگر دانشگاه) توسعه یابد.

## ۱. نسخهٔ API

- نسخهٔ فعلی قرارداد: **v1** (ثابت `API_VERSION` در `src/server/app.ts`).
- هر مسیر هم در `/api/<module>/...` (نام مستعار بدون نسخه = آخرین نسخه) و هم در `/api/v1/<module>/...` سرویس می‌شود؛ هندلرها یکی‌اند.
- هر پاسخ API سرآیند `X-API-Version: 1` دارد.
- کلاینت‌های خارجی (اپ، API عمومی آینده) **باید** از مسیر نسخه‌دار `/api/v1` استفاده کنند؛ وب‌اپ خود سامانه که همراه سرور منتشر می‌شود می‌تواند از مسیر بدون نسخه استفاده کند.
- بررسی‌های مبتنی بر مسیر (حالت تعمیرات، استثنای status پنل طراح، کلید رسانه) نسخه را نادیده می‌گیرند (`apiPath`).

## ۲. چه تغییری در v1 مجاز است (افزایشی)

| مجاز در v1 | نیازمند v2 |
|---|---|
| افزودن endpoint جدید | حذف یا تغییر نام endpoint |
| افزودن فیلد جدید به پاسخ | حذف/تغییر نام/تغییر نوع فیلد موجود |
| افزودن پارامتر اختیاری (مثل `?cursor`, `?limit`) | اجباری کردن پارامتری که قبلاً اختیاری بود |
| افزودن مقدار جدید به `code` خطا | تغییر معنای کد وضعیت HTTP یک حالت موجود |
| سخت‌تر کردن اعتبارسنجی ورودی نامعتبر | تغییر شکل بدنهٔ خطا `{ error, code, request_id }` |

کلاینت‌ها باید فیلدهای ناشناخته را نادیده بگیرند. نمونه: صفحه‌بندی cursor فیلد `next_cursor` را افزود و بدون `?cursor` همان صفحهٔ اول را برمی‌گرداند؛ پس تغییری سازگار در v1 بود.

### بدنهٔ خطا و اعتبارسنجی یکپارچه (zod)

همهٔ خطاها از `HttpError` (`src/server/lib/errors.ts`) و `app.onError` می‌گذرند و یک شکل دارند:

```json
{ "error": "«عنوان» الزامی است", "code": "validation", "fields": { "title": "«عنوان» الزامی است", "count": "«تعداد» نباید کمتر از 1 باشد" }, "request_id": "…" }
```

- `error`: پیام فارسی قابل نمایش به کاربر (همیشه موجود). `code`: کد ماشینی اختیاری (`validation`، `csrf`، `not_finished`، …).
- `fields` (افزایشی در v1): فقط برای ورودی‌های شیء‌محور؛ نگاشت مسیر فیلد → پیام فارسی همان فیلد. اعتبارسنجی تک‌مقداری این کلید را ندارد.
- لایهٔ `src/server/lib/validate.ts` تنها پیاده‌سازی اعتبارسنجی است: طرح‌های فیلد `v.str/int/oneOf/bool/id/list`، و `parseBody/parseQuery/parseInput` برای شیء کامل. توابع قدیمی `str()/int()/oneOf()` در `lib/util.ts` همین طرح‌ها را صدا می‌زنند، پس پیام‌ها در کل API یکسان‌اند.
- هر `ZodError` که از یک `.parse()` بیرون بزند در `onError` به همین بدنهٔ 400 ترجمه می‌شود؛ پیام پیش‌فرض zod هم با `z.config` فارسی شده است.
- آزمون واحد `validation: …` در `tests/unit.mjs` پیام‌ها، تبدیل نوع و گزارش چندفیلدی را قفل می‌کند.

## ۳. انتشار نسخهٔ جدید (v2)

1. ماژول‌های تغییرکرده در `/api/v2/...` اضافه می‌شوند؛ v1 دست‌نخورده می‌ماند.
2. پاسخ‌های v1 سرآیندهای `Deprecation: true` و `Sunset: <تاریخ>` می‌گیرند.
3. v1 دست‌کم **یک سال تحصیلی کامل** پس از انتشار v2 پشتیبانی می‌شود.
4. تغییر در `CHANGELOG.md` و `docs/API_SHAPES.md` ثبت می‌شود.

## ۴. مایگریشن‌های بدون توقف

مایگریشن‌ها در `migrations/NNNN_name.sql` و فهرست `MIGRATIONS` در `src/server/migrate.ts` ثبت می‌شوند و هنگام اولین درخواست، یک‌بار و به‌ترتیب اجرا می‌شوند (جدول `_migrations`). قواعد:

1. **فقط افزایشی:** `CREATE TABLE/INDEX IF NOT EXISTS` و `ALTER TABLE ... ADD COLUMN` (با مقدار پیش‌فرض یا nullable).
2. **ممنوع در یک مرحله:** `DROP TABLE`، `DROP COLUMN`، `RENAME`، تغییر نوع ستون، `NOT NULL` بدون `DEFAULT`. آزمون واحد `migrations are additive` این را کنترل می‌کند.
3. **حذف/تغییر نام در سه مرحله (expand → migrate → contract):**
   - انتشار ۱: ستون/جدول جدید اضافه می‌شود؛ کد در هر دو می‌نویسد و از جدید می‌خواند (با بازگشت به قدیم).
   - انتشار ۲: دادهٔ قدیمی با اسکریپت idempotent منتقل می‌شود.
   - انتشار ۳ (دست‌کم یک انتشار بعد): ستون قدیمی دیگر خوانده نمی‌شود؛ حذف فیزیکی فقط با مایگریشن صریح و پس از پشتیبان‌گیری.
4. **برگشت‌پذیری:** هر مایگریشن در توضیح سرفایل راه برگشت را می‌نویسد (مثلاً «reversible by DROP INDEX»). چون تغییرات افزایشی‌اند، برگشت کد به نسخهٔ قبل بدون برگشت پایگاه داده امن است (نسخهٔ قدیم ستون‌های جدید را نادیده می‌گیرد).
5. **ایندکس‌ها:** با `IF NOT EXISTS`؛ پیش از افزودن، کوئری با `tests/query-plan.mjs` سنجیده می‌شود.
6. **پیش از هر انتشار:** پشتیبان خودکار روزانه + آزمون بازیابی (`docs/RECOVERY.md`).
